## ⏳ 아직 정해지지 않은 것

### 🔴 리프트 명령 다운링크

젯슨에서 리프트로 **"이 높이로 올려줘"** 를 보내는 패킷이 없다.
현재는 현재높이 업링크(`<I,...>` 의 `lift_mm`)만 있다.

제안 형태:

```
젯슨 → ESP32 #1    <L,target_mm>\n
    target_mm : 목표 높이 [mm]
    예)  <L,700.0>
```

젯슨 쪽은 이미 `/lift_cmd_mm` 로 목표높이를 발행 중이라, 포맷만 정해지면 바로 연결된다.
**이게 정해져야 데모 시퀀스(침상 정지 → 리프트 상승 → 회전 → 퇴출)가 완주된다.**

같이 정할 것 —

- `lift_mm` 기준면: 완전히 접힌 상태가 0인지, 다른 값인지
- 도달 판정: `lift_mm` 수렴으로 볼지, 별도 완료 신호를 둘지
- 가동 범위: 100~740mm 유지되는지

### 🟡 3D 프린트 완료 예정일

일정 역산 기준점.

## 📐 조립 후 (부하 상태) 재측정할 값

위 구동 파라미터는 **무부하(바퀴 공중)** 기준 8/13 실측값이다. 조립 후 부하가 걸리면 달라지므로 다시 잡는다.
절차와 도구는 [`hanium_구동계_캘리브레이션_절차_0807.md`](hanium_구동계_캘리브레이션_절차_0807.md).

| 값 | 무부하 (8/13) | 부하 상태에서 확정할 것 |
|---|---|---|
| `ff_gain` | 15.0 | 부하 시 같은 PWM에 각속도가 떨어짐 → 재측정 |
| `deadband_pwm` | 25 | 바닥 마찰 + 로봇 무게로 커짐 → 재측정 |
| `max_wheel_omega` | 8.0 | 부하 최대속도 재확인 |
| 휠 유효반경 | 0.040145 m (CAD, 🔴 미확정) | 직진 2m 실측 vs 오도메트리로 역산 |
| 트랙폭 / 휠베이스 | 206.99 / 192.05 mm (STEP) | 제자리 90°/180° 회전으로 검증 |
| `wheel_sign` / `enc_sign` | 확정 (위 ✅) | 배선을 다시 했을 때만 재확인 |

## 🔗 정해지면 반영되는 곳

접점이 확정될 때 어느 파일이 바뀌는지. **바꾸기 전에 상대 팀에 알린다.**

| 확정 항목 | 반영 위치 |
|---|---|
| 리프트 패킷 | `serial_protocol.py` 다운링크 추가 + `serial_bridge_node.py` `/lift_cmd_mm` 구독 |
| `lift_mm` 기준면 | `lift_tf_node.py` 의 `lift_mm_is_absolute` |
| 섀시 최종 치수 | `nav2_care.yaml` local/global footprint |
| 라이다 높이 | `smart_upcare.urdf.xacro` 의 `lidar_link` |
| 캘리브레이션 값 | `serial_bridge_node.py` 파라미터 기본값 |
| ESP32 #2 연결 | `robot_bringup.launch.py` 의 `enable_esp2` |

> `enable_esp2` 는 당분간 `false` 유지. ESP32 #2 펌웨어가 아직 없고,
> 포트 고정 경로(`by-id`/`by-path`)가 안 정해진 상태에서 켜두면 엉뚱한 장치를 열 수 있다.
