# 깃허브 저장소 세팅 — 한 번만 하면 됨

> 순서대로 복붙하면 됩니다. 15~20분.
> 명령은 **윈도우 PowerShell** 기준. (리눅스면 `mv`/`rm -rf`/`cp -r` 로 바꾸면 동일)
> 다 끝나면 이 파일은 지우셔도 됩니다.

---

## 0. 정리 — 커밋 전에 지울 것

작업하면서 남은 찌꺼기입니다. `.gitignore` 로도 걸리지만 폴더가 깔끔한 게 낫습니다.

```powershell
cd C:\hanium\hanium_ws

# 세션 중 남은 임시 파일 (제가 만든 것들 — 지워주세요)
Remove-Item -Force .probe2 -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .git_probe -ErrorAction SilentlyContinue
Remove-Item -Force tools\calib_result_TEST.json -ErrorAction SilentlyContinue

# 파이썬 캐시 (오래된 .pyc 가 섞이면 헷갈립니다)
Get-ChildItem -Recurse -Directory -Filter __pycache__ | Remove-Item -Recurse -Force
```

## 1. 폴더 구조 정리

문서를 `docs/` 로 모으고, 아두이노 펌웨어를 가져옵니다.

```powershell
cd C:\hanium\hanium_ws

# docs/ 로 문서 이동 (README.md 는 루트에 남김)
New-Item -ItemType Directory -Force docs
Move-Item *.md docs\
Move-Item docs\README.md .          # README 는 루트로 되돌림

# 아두이노 펌웨어 가져오기 (구동팀 폴더에서)
New-Item -ItemType Directory -Force arduino
Copy-Item -Recurse `
  "C:\Users\admin\Desktop\프로젝트\한이음\smart_upcare_실차통합_구동통합\arduino\smart_upcare_uno" `
  arduino\

# 구동팀 회신 문서도 같이 (프로토콜 근거 자료)
Copy-Item `
  "C:\Users\admin\Desktop\프로젝트\한이음\smart_upcare_실차통합_구동통합\README_아두이노구동_통합.md" `
  docs\
```

끝나면 이렇게 됩니다.

```
hanium_ws/
├── README.md
├── .gitignore
├── src/
├── arduino/smart_upcare_uno/
├── tools/
└── docs/            ← md 전부
```

## 2. 깃허브에 빈 저장소 만들기

|---|---|
| Repository name | `smart-upcare` |
| 공개 범위 | **Private** ← 대회 제출 전까지 |

만든 뒤 나오는 주소를 복사해둡니다. (`https://github.com/<아이디>/smart-upcare.git`)

## 3. 첫 커밋 & 푸시

```powershell
cd C:\hanium\hanium_ws

git init
git branch -M main

# 처음이면 한 번만
git config user.name  "구영인"
git config user.email "yeongink27@gmail.com"

git add -A
git status                # ★ build/ install/ log/ __pycache__ 안 잡히는지 눈으로 확인

git commit -m "초기 커밋 — ROS 워크스페이스 + UNO 펌웨어 + 캘리브레이션 도구

- src/: Nav2·EKF·시리얼 브리지·URDF (8/7 실차 대비 수정 반영)
- arduino/: UNO 펌웨어 (구동팀 실차 검증본)
- tools/: 캘리브레이션 도구 + 테스트 (ROS 없이 동작)
- docs/: 핸드오프·체크리스트·진단기록"

git remote add origin https://github.com/<아이디>/smart-upcare.git
git push -u origin main
```

> `git status` 에서 `build/`, `install/`, `log/`, `__pycache__`, `*.mp4` 가 보이면
> `.gitignore` 가 안 먹은 겁니다. 파일이 `hanium_ws/.gitignore` 에 있는지 확인하세요.

```
처음 받을 때:
  git clone https://github.com/<아이디>/smart-upcare.git

작업할 때 (main 에 직접 푸시하지 말고 브랜치로):
  git switch -c firmware/엔코더보호     # 이름은 자유
  ...작업...
  git add -A
  git commit -m "무엇을 왜 고쳤는지"
  git push -u origin firmware/엔코더보호
  → 깃허브에서 Pull Request 만들면 내가 볼게

폴더 설명이랑 프로토콜은 README.md 에 정리해뒀어.
```

## 6. 앞으로

**측정값은 커밋하지 않습니다.** `calib_result.json` 은 무시 목록에 있어요.
확정되면 launch 기본값이나 yaml 에 반영하고, **그 커밋 메시지에 근거를 남기는 게**
나중에 "이 숫자 왜 이래?" 할 때 답이 됩니다.

```bash
git commit -m "wheel_sign/enc_sign 실측 반영

캘리브레이션 결과 우측 2바퀴는 모터 극성만 반대이고 엔코더는 정상.
wheel_sign=[1,1,-1,-1], enc_sign=[1,1,1,1]"
```

**데모 영상은 깃에 넣지 마세요.** `.mp4` 는 무시 목록에 있습니다.
구글드라이브나 노션에 두고 `docs/` 문서에 링크만 거는 게 맞아요.

**심사 대비.** 커밋 히스토리 자체가 개발 과정 자료가 됩니다. 특히 이런 것들 —
micro-ROS 기각, ORB-SLAM3 를 Nav2 백본에서 제외, 라이다 전용 마운트 결정.
"왜 이렇게 했나" 질문에 그대로 답이 됩니다.
